# Nightly code audit — 2026-07-31

Automated, report-only static audit of ShopCommand (AddyBrusse/MaterialManager). No database or running
app was available in this environment; all findings come from reading code, Zod schemas, the Prisma
schema, and running the TypeScript/build/test toolchain. Six subagents covered the app in parallel
(Materiaalbeheer, Stamgegevens, Productie, Planning/mobile/settings, a cross-cutting redundancy sweep,
and the shared/API/Prisma type-drift layer), each verifying findings by reading the actual call paths
before reporting them.

## Functionality risks

### High

1. **`apps/api/src/routes/low-stock.ts:19-20`** — Prisma `Decimal` objects compared with raw `<` do a
   **lexicographic string comparison**, not numeric. `currentStock=9 < minStock=10` evaluates the strings
   `"9" < "10"`, which is `false` (since `'9' > '1'`), so an item at 9 with a minimum of 10 is silently
   **excluded** from the low-stock list. Every other route in the codebase calls `.toNumber()` first;
   this route is the outlier. **Fix:** `Number(r.currentStock) < Number(r.minStock)`.

2. **`apps/api/src/routes/projects.ts`** (all ~20 mutation endpoints, e.g. lines 158-165, 216-245,
   388-543) — unlike `raw-materials.ts:76-81` and `finished-goods.ts:42-47`, no project mutation route
   checks the `Lock` table server-side. `apps/web/src/hooks/useProjectLock.ts` only gates the UI
   client-side. Any second client (stale tab, script, direct API call) can mutate a project while
   another user holds the edit lock, silently clobbering their session. **Fix:** apply the same
   lock-ownership check used in raw-materials/finished-goods to `withProject`, or document the
   deliberate opt-out.

3. **`apps/web/src/routes/desktop/VoorraadPage.tsx:618`** — `allReservations` is captured once via
   `useState(() => reservationsStore.list())` with no setter ever called and no `useEffect` to
   re-sync once `useInitAppData()`'s async fetch resolves. `ReserveringenPage.tsx:270-272` has the
   identical read pattern but explicitly fixes it with an effect. On a fresh load/refresh of
   `/voorraad`, the "Gereserveerd" column and `ItemDrawer` reservation list can show 0/stale data for
   the rest of the session. **Fix:** mirror `ReserveringenPage`'s `useEffect` + real setter.

4. **`apps/web/src/routes/desktop/VoorraadPage.tsx:21-27,553-570`** — the item detail drawer's
   "Historie" tab renders a hardcoded module-level `MOCK_HISTORY` array (fake dates, fake order numbers
   like `WO-2026-0331`) for **every** raw material, unconditionally — never filtered by `row.id`, never
   fetched from the real `GET /api/movements?itemId=` endpoint that already exists and is used
   elsewhere in the same file (`MutatieModal`). Every material's drawer shows identical, unrelated fake
   history. **Fix:** fetch real movement history by `itemId`; remove `MOCK_HISTORY`.

5. **`apps/web/src/api/articles.ts:214-223`** — `articlesApi.create()` computes the new article's `id`
   client-side via `nextArtNo()` over a per-browser, in-memory snapshot loaded once at startup. Two
   users creating an article around the same time with equally-stale caches can compute the same
   `ART-####`; the server's `prisma.article.create` (given an explicit id, bypassing the atomic
   `doc_sequences` sequence entirely) throws a unique-constraint 500 for the second one — which is
   silently swallowed by a bare `.catch(() => {})`. That user is left editing what's actually the first
   user's article, and later autosave PATCHes overwrite the first user's real data. **Fix:** let the
   server always assign the id (drop client-supplied `id` from the POST body), and stop swallowing the
   create failure.

### Medium

6. **`apps/api/src/routes/locks.ts:41-75`** — `/acquire` does check-then-act (`findUnique` then
   `create`) with no transaction, on a table with composite PK `@@id([itemType, itemId])`. Two users
   opening the same record within the same instant can both pass the "no existing lock" check; the
   second `create` throws an uncaught unique-constraint error, surfacing as a generic 500
   ("Interne serverfout") instead of the intended `409 LOCK_HELD`. This is the app's core locking
   mechanism. **Fix:** catch the P2002 violation and translate to `AppError(409, 'LOCK_HELD', ...)`.

7. **`apps/api/src/services/label.ts:6-25`** — `reserveLabelBatch` reads the highest existing label
   number then does an unguarded `createMany`, with no transaction/row lock (contrast with the atomic
   `doc_sequences` UPSERT used for project/article numbering). Two concurrent "print labels" requests
   can compute the same next-number range; the second batch insert throws on the unique `Label.number`
   constraint. **Fix:** wrap in a transaction with row-level locking, or move onto `doc_sequences`.

8. **`apps/api/src/services/weight.ts` + `packages/shared/src/schemas/profile.ts`** — `volumeM3()`
   hardcodes the dimension keys each formula expects (`diameter`, `side`, `width`/`height`, etc.), but
   `CreateProfileSchema` allows an admin to name `dimensionSchema` keys arbitrarily, with no cross-check
   against the chosen `volumeFormula`. A mismatched key (e.g. `diam` instead of `diameter`) makes
   `calcWeightKg` return `NaN`, which `JSON.stringify` silently turns into `null` in the API response —
   no error anywhere in the pipeline. **Fix:** add a Zod `.refine()` requiring `dimensionSchema` to
   contain the keys the selected `volumeFormula` needs.

9. **`apps/web/src/components/projecten/OfferteTab.tsx`** (`RegelForm`, edit path) — the "Artikel
   (optioneel)" selector lets a user pick a different linked article when editing an existing regel, but
   `handleSave`'s edit branch only sends `naam/omschrijving/qty/eenheid/verkoopprijs` to
   `projectsApi.updateOfferteRegel` — both the client patch type and the server's `UpdateRegelSchema`
   omit `artikelId`/`bewerkingen`. Changing the article in the dropdown and saving silently no-ops; the
   regel keeps its original link. **Fix:** hide the selector in edit mode, or extend both schemas to
   accept and persist the field.

10. **`apps/web/src/routes/desktop/ZaagCalculatorPage.tsx:152-155`** — `toggleBar`'s
    `stillNeeded || maxPieces` treats an already-fully-planned `stillNeeded === 0` as "unset" (since `0`
    is falsy), pre-filling the reservation input with the bar's full capacity instead of `0` once the
    needed quantity is already covered by other selected bars — risking over-reservation. **Fix:** use
    `stillNeeded > 0 ? stillNeeded : 0` instead of `||`.

11. **`apps/api/src/routes/movements.ts:36-51`** — `POST /movements` computes and writes `newStock`
    with no check against going negative, though `features/32-stock-movements.md` documents this should
    be rejected. Not reachable from the current Voorraad UI (which clamps client-side), but the generic
    endpoint has no server-side guard for any other/future caller. **Fix:** reject with 400 if
    `newStock < 0` inside the transaction.

12. **`apps/web/src/components/raw-materials/RawMaterialForm.tsx` + `apps/web/src/api/locations.ts:85-94`**
    — `locationsApi.list()`/`createLocation()` swallow all fetch errors and fall back to fabricated mock
    location IDs (e.g. `s1a`). If the API blips while the form is open, a user can submit a
    `locationSlotId` that doesn't exist as a real row; the DB's FK constraint then throws an unhandled
    500 rather than a validation error. **Fix:** don't silently mask fetch failures for reference data
    feeding a real FK.

13. **`apps/web/src/api/overhead.ts`** — Bedrijfskosten/Machines overhead config
    (`hoursPerDayOverride`, `utilizationPct`, shop rates) is still pure per-browser `localStorage`, with
    no API/Prisma backing — despite the 2026-06-22 decisions-log entry explicitly naming "overhead" as
    owed this migration, now over a month overdue. With ~4 users on separate machines, an admin's
    Bedrijfskosten changes don't propagate to anyone else's Prognose/planning view. **Fix:** migrate to
    a Prisma model + `/api/overhead` route, matching how `machines.ts` was already migrated.

### Low

14. `apps/web/src/routes/desktop/RelatieDetailPage.tsx:82-86` — `toggleActief` invalidates only
    `['relaties', id]`, not `['relaties']`, unlike `RelatieGegevensTab.tsx`/`RelatieContactenTab.tsx`
    which correctly invalidate both. A background Relaties-list tab (kept mounted via the global tab
    bar) can show a stale Actief/Inactief badge after a toggle elsewhere.

15. `apps/web/src/components/planning-queue/QueueDetails.tsx:26-28` — `onClose`, `onUnplan`,
    `onSetHold` props are passed by `PlanningQueuePage.tsx` but never wired to any button inside
    `QueueDetails`. The Hold feature is fully implemented end-to-end elsewhere but has no UI entry
    point; same for un-planning from the detail panel (only drag-to-backlog works).

16. `apps/web/src/components/todos/useTodoAlerts.ts:19-28` — the alert `useMemo`'s deps
    (`[rawData, finishedData, projects, articles]`) omit `grades`/`profiles`/`machines`, which are also
    read via `listSync()` inside the memo; a rate/grade edit alone won't trigger recompute until another
    tracked dep changes (self-corrects on the next 20s poll, so low impact).

17. `apps/api/src/routes/relaties.ts:20-26` — `GET /:id` uses `findUniqueOrThrow` with no try/catch,
    unlike every other entity route; a nonexistent relatie throws an uncaught Prisma P2025 that falls
    through to a generic `500` instead of the expected `404`.

18. `apps/api/src/routes/labels.ts:19-29` — `status` query param is cast directly to the Prisma enum
    type without validating via the shared `LabelStatusSchema`; a garbage value throws at the DB-driver
    level (500) instead of a clean 400.

19. `apps/api/src/routes/todos.ts:79-90` — `/:id/complete` reads `Boolean(req.body?.done ?? true)`
    instead of parsing with Zod; `Boolean("false")` is `true`, so a client sending the string `"false"`
    would mark a todo done. The current frontend always sends a real boolean, so not triggered today.

20. `apps/web/src/routes/desktop/BinnenBoekenPage.tsx:52-53` and
    `apps/web/src/routes/desktop/ProjectenPage.tsx:167,254` — several primary buttons ("Concept
    opslaan", "Verwerken", "Exporteer", "Meer filters") have no `onClick` at all, unlike the rest of the
    app's stubbed actions which at least show a "binnenkort beschikbaar" notification.

**Not found (verified, worth recording as a negative result):** weight is confirmed genuinely
computed-on-read everywhere (`grep` for `weightKg`/`densityKgM3`/`volumeFormula` across the whole repo
turns up only read-time call sites); the round/square/flat/tube formula itself is dimensionally correct.
Mobile routes (`/raw`, `/finished`, `/movements`) are confirmed literal placeholders matching documented
"not yet built" status — nothing to break there yet.

## Code redundancy

### Medium/High impact

21. **`apps/api/src/services/offerte-pdf.ts` + `apps/api/src/routes/pdf.ts`** — the entire server-side
    PDF generation path (pdfkit) is wired into Express (`app.use('/api/pdf', ...)`) but has **zero**
    callers in the frontend; offerte PDFs are generated entirely client-side via a separate jsPDF
    implementation (`apps/web/src/services/offerte-pdf.ts`). The server version also hardcodes a stale
    company-info constant that has drifted from the real settings-driven data. `pdfkit`/`@types/pdfkit`
    exist solely to support this dead path. **Action:** remove the route/service/deps, or wire the
    frontend to use it instead of the duplicate client implementation.

22. **`apps/web/src/api/raw-materials.ts:64-79`** (`computeWeightKg`) vs
    **`apps/api/src/services/weight.ts:3-32`** (`volumeM3`/`calcWeightKg`) — the same weight/volume
    formula is independently hand-reimplemented client- and server-side (different intermediate units),
    with no shared source despite CLAUDE.md describing it as one formula. **Action:** move into
    `packages/shared` and import from both apps.

23. **Currency/date formatting duplicated ~10×** across `apps/web/src` — `€`/`nl-NL` currency
    formatting is independently redefined in `ArticleFinancialCard.tsx`, `ArticleCalculator.tsx`,
    `ArticleSankey.tsx`, `BedrijfskostenTab.tsx`, `OverheadTab.tsx`, both PDF services, `api/projects.ts`,
    and `ArtikelenPage.tsx`; Dutch date formatting is similarly re-typed with slightly different option
    objects in several more files. No `formatEUR`/`formatDateNL` helper exists anywhere. **Action:** add
    `apps/web/src/utils/format.ts` and migrate call sites incrementally.

24. **`apps/api/src/routes/articles.ts` and `apps/api/src/routes/reservations.ts`** — Article
    (estimate/calculator) and Zaag-reservation data have **no schema in `packages/shared` at all**; both
    routes hand-roll local Zod validators (with `recipe`/`operations`/`estimate`/`attachments` typed as
    bare `z.unknown()` — effectively no shape validation for the fields driving the kostprijs
    calculator), and the frontend re-declares matching shapes locally. This is the only place the
    "shared schema → Prisma → route → frontend" build order from CLAUDE.md is dropped entirely.
    **Action:** add `packages/shared/src/schemas/{article,reservation}.ts` and route both sides through
    them.

### Low impact

25. `packages/shared/src/**/*.js.map` (10 stray files: `index.js.map`, `finished-good`, `grade`,
    `label`, `location`, `lock`, `movement`, `profile`, `raw-material`, `user`) — build-artifact
    sourcemaps checked into git next to the `.ts` sources, not covered by `.gitignore` (which only
    excludes `dist/`). Newer schema files have no matching `.js.map`, confirming these are leftovers
    from an old misconfigured `tsc` run. **Action:** `git rm` them.

26. `apps/web/src/routes/desktop/TableSort.module.css` — zero imports anywhere in the repo (confirmed:
    no `.tsx`/`.ts` file imports any CSS module by that name). **Action:** delete.

27. `recharts` (declared in `apps/web/package.json`) — zero imports anywhere in `apps/web/src`; the
    app's chart-like views (`PrognoseBars.tsx`, `PrognoseHeatmap.tsx`) are hand-rolled. **Action:**
    remove the dependency.

28. `@mantine/charts` — only its CSS is imported (`main.tsx`); no chart component from the package is
    ever used. Lower confidence than #27 since the CSS import could be deliberate prep for future use —
    flagged for visibility, not a clear-cut removal.

29. `apps/web/src/components/articles/ArticleForm.tsx` (`mode="add"` branch, ~lines 43-148) — dead:
    "Nieuw artikel" calls `articlesApi.create()` directly (`ArtikelenPage.tsx:115-125`) rather than
    rendering this form in add mode, leaving its `nextArtNo` preview block and an editable "Huidig"
    stock field (which contradicts stock being movement-managed elsewhere) unreachable.

30. `apps/api/src/routes/locations.ts:11-14` — `CreateSlotBodySchema` re-declares fields already
    present in the shared `CreateLocationSlotSchema` instead of `.omit()`-ing from it; a future
    constraint change to the shared schema wouldn't propagate here.

31. `packages/shared/src/schemas/grade.ts:7` vs `apps/api/src/routes/grades.ts` — `pricePerKg` is
    `.optional()` in the Zod schema (allows `undefined`) but the API always serializes an explicit
    `null` when absent — a static type-contract mismatch, not an observed runtime bug (no consumer
    currently breaks on it).

32. `apps/web/src/api/{grades,locations,surface-finishes,profiles}.ts` — still carry a full parallel
    localStorage-mock CRUD fallback layer alongside the real API calls, left over from before the
    2026-06-22 "mock phase ended" decision (not a new violation, just old code worth trimming now that
    the real backend is the only supported path).

**Not found (verified, worth recording as a negative result):** no `TODO`/`FIXME`/`XXX`/`HACK` markers
exist anywhere in `apps/web/src`, `apps/api/src`, or `packages/shared/src`. No orphaned/unwired page
files — every route under `apps/web/src/routes/desktop/` is registered in `pageRegistry.tsx`/
`AppLayout.tsx`. No unused exports from `packages/shared`'s barrel. No locally-redefined duplicates of
shared *entity* schemas (route-local validators found are narrow, request-specific, e.g. accept/hold
body shapes). The parked "operator terminal" app (`03-parked.md`, `features/50-operator-terminal.md`) is
confirmed genuinely absent — no `apps/operator`, no imports referencing it. All other declared
dependencies in every `package.json` (root, web, api, shared) were checked and have live imports.
