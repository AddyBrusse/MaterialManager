## Functionality risks

### High

1. **Toevoegen/Afboeken on Voorraad race — silently overwrites concurrent stock changes.**
   `apps/web/src/routes/desktop/VoorraadPage.tsx:306-327` (`MutatieModal.handleSubmit`) always computes the new absolute stock client-side from a snapshotted `row.currentStock` and calls `rawMaterialsApi.adjustStock(...)`, which (`apps/web/src/api/raw-materials.ts:120-127`) *always* POSTs `kind: 'overwrite'` — `kind: 'delta'` is defined in the schema but never used anywhere in the codebase.
   *Failure scenario*: item shows 1200mm; user A opens "Toevoegen" while user B records a correction to 700mm; user A's "+300" submits `overwrite amount=1500`, discarding B's correction. Defeats the concurrency protection `workflows/42-adjust-stock.md` describes.
   *Fix*: send `kind:'delta'` with a signed amount for Toevoegen/Afboeken; reserve `overwrite` for Correctie only.

2. **Voorraad "Historie" panel shows fabricated data for every item.**
   `apps/web/src/routes/desktop/VoorraadPage.tsx:21-27,555` renders a hardcoded `MOCK_HISTORY` array (fake supplier names/order numbers) in every item's detail drawer, regardless of which item is open. `GET /api/movements?itemId=...` (`apps/api/src/routes/movements.ts`) is fully implemented server-side, but no frontend wrapper or call to it exists anywhere in `apps/web/src` — confirmed by search. The "Geschiedenis" footer button just shows a "binnenkort beschikbaar" toast.
   *Failure scenario*: any user opens any raw material and sees invented receipt/usage history unrelated to that item — misleading operational data.
   *Fix*: add a `movementsApi.list({itemId})` wrapper and replace `MOCK_HISTORY`.

3. **Create/update fallback silently fabricates fake "success" records when the API call fails, across five admin modules.**
   `apps/web/src/api/{grades,profiles,machines,locations,relaties}.ts` — every `create`/`update`/`remove` wrapper wraps `apiFetch` in a try/catch that treats *any* failure (validation 400, auth 403, 500, or the 3s abort timeout) as "offline," and returns a synthetic, non-persisted record as if the call succeeded. Confirmed end-to-end for relaties: `RelatiesPage.tsx:39-46` navigates to the fake id immediately after `create()`, and `relatiesApi.get()` (`relaties.ts:102-107`) happily serves the fake item from its local cache on the resulting 404.
   *Failure scenario*: an admin adds a Relatie/grade/profile/machine/location while the backend rejects it (e.g. a validation error, or `requireAdmin` 403 for a non-admin) — the UI reports success and shows the new item, but nothing was persisted; the record silently disappears on next reload/other device.
   *Fix*: mock-phase ended per CLAUDE.md — remove the catch-and-fabricate fallback; surface errors via `onError`/notifications instead.

4. **`FinishedGood` legacy table is empty in practice but still backs live features.**
   The real "artikelen" catalog is the `Article` Prisma model (served by `apps/api/src/routes/articles.ts`). The older `FinishedGood` model has no live create path (its only `POST` route has zero frontend callers), yet `apps/web/src/utils/todoAlerts.ts:45-73`'s low-stock alert still calls `finishedGoodsApi.list()`, and `GET /api/search?type=finished` (`apps/api/src/routes/search.ts:43-60`) still queries `prisma.finishedGood`.
   *Failure scenario*: an article's stock drops below minimum — the Todos low-stock signalering never fires for it, because it's reading a permanently-empty table.
   *Fix*: point both call sites at `Article`, or finish removing `FinishedGood`/its route/wrapper (per the existing 2026-06-04 decision-log entry).

5. **Wachtrij (planning-queue) "Op schema / Te laat" status is computed backwards, so almost every job shows red.**
   `apps/web/src/components/planning-queue/QueueDetails.tsx:56` (and the per-step equivalent at `:124`) computes `isLate = required && job.deadline && required < job.deadline`, instead of comparing the *derived schedule finish* against `required` — the correct pattern already used elsewhere in the same feature (`isAtRisk` in `QueueTimeline.tsx:222`, `QueueBacklog.tsx:51`, `QueuePanel.tsx:87`). `required` (`verplichtKlaar`) is backward-planned from the deadline and is, by construction, `<= deadline` for every step except the very last one in an order.
   *Failure scenario*: this condition is true for nearly every non-final step regardless of actual schedule risk — the header pill and per-step dot show "Te laat" almost all the time, even for jobs comfortably on schedule, making the panel's primary risk indicator effectively useless.
   *Fix*: replace with `isAtRisk(job, schedule.get(job.id), required, windowStart)`, matching the rest of the feature.

6. **Editing an offerte-regel's linked artikel is silently discarded on save.**
   `apps/web/src/components/projecten/OfferteTab.tsx:116` (the "Artikel (optioneel)" select in the edit drawer) is always enabled and updates local `artikelId`/`bewerkingen` state, live-reflected in the "Productie stappen" preview. But `handleSave()` (`:90-94`) only sends `{ naam, omschrijving, qty, eenheid, verkoopprijs }` to `projectsApi.updateOfferteRegel` — `artikelId`/`bewerkingen` aren't in the payload, and the server's `UpdateRegelSchema` (`apps/api/src/routes/projects.ts:247-253`) doesn't even accept those fields.
   *Failure scenario*: a user re-links a mis-selected artikel via "Bewerken", sees the preview update, clicks "Opslaan" — the regel silently keeps the old `artikelId`, with no error. `RegelsTable`'s kostprijs/materiaal/thumbnail (keyed off `artikelId`) stay wrong.
   *Fix*: either hide the artikel select in edit mode, or include `artikelId`/`bewerkingen` in the update payload and both Zod/route schemas.

7. **Article `klant`/`relatieId` can desync via the list-page edit form.**
   `apps/web/src/components/articles/ArticleForm.tsx:96-98` lets a user retype the free-text `klant` field on the "Bewerken" action from `ArtikelenPage.tsx:342`, but unconditionally preserves the *existing* `relatieId`/`contactId`. The detail page's own inline editor treats the two as coupled.
   *Failure scenario*: admin retypes `klant` to a different customer's name via the list-page modal — the header shows the new name, but `relatieId` still points at the old Relatie, so the Contact dropdown and `RelatieArtikelenTab` linkage stay pinned to the wrong company.
   *Fix*: drop the free-text `klant` edit from this form (route customer changes only through the detail page's Autocomplete), or clear `relatieId`/`contactId` when `klant` changes here.

### Medium

8. **No row lock / no non-negative check on stock movements.** `apps/api/src/routes/movements.ts:28-68` reads `previousStock` via a plain `findUnique` (no `SELECT … FOR UPDATE`) and never rejects a negative `newStock`, though both are required by `features/32-stock-movements.md`. Today's only caller clamps client-side, but the endpoint itself will persist a negative stock or lose an update under concurrent writes for any future caller. *Fix*: wrap in a locking transaction and reject `newStock < 0`.
9. **Zaagflow stock write after a cut fails silently.** `apps/web/src/routes/desktop/ZaagflowPage.tsx:192-194` — `rawMaterialsApi.adjustStock(...).catch(() => {})`; the reservation is marked `done` unconditionally just above, regardless of whether the stock write actually succeeded. *Fix*: surface a notification on failure; don't advance to "done" without confirming the write.
10. **"Productie loopt uit" alert fires on jobs that just started.** `apps/web/src/utils/todoAlerts.ts:102-134` measures elapsed time from `ProductieOrder.createdAt`, which is set once at order creation, not when production actually starts. *Failure scenario*: an order queued for two weeks then started immediately trips the overrun alert the moment its first step is checked off. *Fix*: track an actual "started" timestamp instead of `createdAt`.
11. **Deleting a Relatie leaves dangling references on its articles.** `apps/api/src/routes/relaties.ts:57-63` deletes the row with no cleanup of `Article.relatieId`/`contactId` (no FK exists). The UI's own delete-confirmation text ("linked articles lose the relation") doesn't match what actually happens — the link becomes unresolvable, not cleared. *Fix*: null out linked articles' `relatieId`/`contactId` before/with the delete.
12. **Article `recipe` isn't cleared when its material line is removed.** `apps/web/src/routes/desktop/ArtikelDetailPage.tsx:140-157` — when no qualifying material node exists, the debounced persist effect spreads `{}` instead of `{ recipe: null }`. *Failure scenario*: removing the only material line leaves a stale `recipe`, undercounting `ArtikelenPage`'s "Zonder recept" stat and showing wrong grade/dimensions elsewhere. *Fix*: explicitly patch `recipe: null` when no material node is found.
13. **Dead, drifted server-side PDF route.** `apps/api/src/routes/pdf.ts` + `apps/api/src/services/offerte-pdf.ts` (mounted at `/api/pdf`) have zero frontend callers — `OfferteTab.tsx` uses a separate client-side `apps/web/src/services/offerte-pdf.ts` (jsPDF) instead. The two have already drifted: the server version hardcodes a `BEDRIJF` constant while the client version pulls live company data. *Fix*: delete the unused server route/service, or wire it up and remove the client duplicate.
14. **`/api/low-stock` is dead, spec-drifted, and has a latent numeric-comparison bug.** `apps/api/src/routes/low-stock.ts` is mounted but has zero frontend callers (the Todos low-stock alert is computed independently in `todoAlerts.ts`); its response shape no longer matches `features/37-low-stock.md`; and it compares Prisma `Decimal` fields with raw `<` (`:19-20`), which is a lexicographic string comparison via `decimal.js-light`, not numeric — currently dormant only because nothing calls the route. *Fix*: delete the route and update the doc, or fix and wire it up.
15. **Nieuw-artikel round-trip from the offerte picker drops the return context.** `apps/web/src/components/projecten/ArtikelPickerModal.tsx:255` builds a `?offerteId=...` query param on the "Nieuw artikel" navigation, but nothing reads it (`ArtikelDetailPage.tsx` only reads `returnTo`). *Failure scenario*: after creating the new article and navigating back, the user must manually reopen the picker and re-search for the article they just made — the flow looks wired up but isn't. *Fix*: read `offerteId` to reopen the picker pre-staged with the new article, or drop the dead param.
16. **Todos routes throw a generic 500 instead of 404 on a since-deleted row.** `apps/api/src/routes/todos.ts:79-111` (`/complete`, `/calendar-event`, `DELETE`) skip the existence check that `/claim` (`:62-77`) does. *Failure scenario*: with 4 users polling every ~20s, one deletes a todo while another acts on the stale row — Prisma's `P2025` isn't special-cased by the error middleware, so it surfaces as "Interne serverfout." *Fix*: add the same `findUnique`/404 guard used in `/claim`.
17. **`QueueDetails` panel has dead buttons and unused handlers.** `apps/web/src/components/planning-queue/QueueDetails.tsx:12-28` — `onClose`, `onUnplan`, `onSetHold` are passed in but never used; "Artikel"/"Tekening"/"Verkenner" buttons (`:98-100`) have no `onClick`. *Fix*: wire these up or remove them from the prop contract/UI.

### Low

18. **`gradesApi`/`profilesApi` don't update their sync cache on a successful write**, unlike the equivalent `machinesApi`/`articlesApi`/`relatiesApi` wrappers (`apps/web/src/api/grades.ts:44-46`, `profiles.ts:70-73`). Consumers of `listSync()` (e.g. `useTodoAlerts`, the Projecten `ArtikelPickerModal`) serve a stale snapshot until a full reload. *Fix*: mirror `machinesApi`'s pattern.
19. **`RelatieDetailPage` header KPIs read `articlesApi.list()` synchronously instead of via `useQuery`**, so they don't re-render when the `['articles']` query is invalidated elsewhere on the same page (`RelatieDetailPage.tsx:76-80`).
20. **Todo "overdue" check doesn't normalize timezone.** `apps/web/src/components/todos/TodoRow.tsx:22` compares `new Date(todo.dueDate)` (parsed as UTC midnight) directly against `now`, flagging a todo due "today" as overdue for most of that day in NL local time.
21. **VoorraadPage takes one lazy, never-refreshed snapshot of reservations** (`VoorraadPage.tsx:618`, `useState(() => reservationsStore.list())`), unlike `ReserveringenPage.tsx`, which works around the same known caching issue with an explicit re-fetch. "Gereserveerd" totals can stay stale/empty for the whole session on first visit.
22. **Client-generated raw-material `code` can collide under concurrent adds.** `RawMaterialForm.tsx:18-22` derives `#NNNNN` client-side from the currently loaded rows; a Prisma `P2002` unique violation on `code` isn't special-cased by `middleware/error.ts`, surfacing as a generic 500. *Fix*: catch `P2002` with a friendly conflict message, and/or generate the code server-side.
23. **Zaagflow loses an explicit "0" rest-length measurement.** `ZaagflowPage.tsx:188` — `restMm || null` maps a genuine `0` to `null` ("not measured").
24. **`ProductieTab` sorts `order.stappen` in place during render** (`ProductieTab.tsx:159`), mutating the same array reference held in `projectsApi`'s cache. Currently benign since `volgorde` is stable, but bypasses the immutable-update pattern used elsewhere.
25. **Relatie `type` is unconstrained in Postgres but restricted in Zod.** `packages/shared/src/schemas/relatie.ts:16` allows only 3 enum values; `apps/api/prisma/schema.prisma:289` stores it as plain `String` with no DB-level check.
26. **`Article` has no shared Zod schema.** `apps/api/src/routes/articles.ts:9-28` validates JSON blob fields as `z.unknown()`, and the frontend `Article` type (`apps/web/src/api/articles.ts`) is a hand-duplicated shape with no compile-time link to the backend — unlike every other domain, which shares a schema via `packages/shared`.

## Code redundancy

### High/medium

27. **PDF-helper code duplicated near-verbatim across three service files**, already drifting. `apps/web/src/services/offerte-pdf.ts:26-146` and `opdrachtbevestiging-pdf.ts:1-137` define identical `formatBedrag`/`formatDatum`/`setColor`/`txt`/`hline`/`fillRect`/`drawTableHeader`/`drawTableRow` helpers (`opdrachtbevestiging-pdf.ts:5` even comments "shared with offerte-pdf"); `productie-pdf.ts:33-69` has a third, independently-diverged copy. *Fix*: extract a shared `pdf-helpers.ts`.
28. **Currency formatting duplicated in 5 files** with the identical one-liner (named `eur` in 3, `euro` in 2): `ArticleFinancialCard.tsx:11-12`, `ArticleCalculator.tsx:18`, `ArticleSankey.tsx:28-29`, `BedrijfskostenTab.tsx:4`, `ArtikelenPage.tsx:21`. *Fix*: consolidate into one `formatEur` export.
29. **`RegelForm`'s "add mode" branches are unreachable dead code.** `OfferteTab.tsx:37-68` — grep confirms `RegelForm` is only ever rendered in edit mode (`edit={editRegel}`, only when `editRegel` is truthy), consistent with CLAUDE.md's documented convention that adding goes exclusively through `ArtikelPickerModal`. The full "Artikel toevoegen" title path and `!edit`-guarded auto-fill logic can never execute.

### Low

30. **Build artifacts committed to source.** 10 `.js.map` files tracked under `packages/shared/src/` with no matching `.js` files alongside — a stale/partial compile leaked into git; `.gitignore` only excludes `dist/`. *Fix*: `git rm` the 10 files and add `*.js.map` to `.gitignore`.
31. **`decisions/90-decisions-log.md`'s 2026-06-15 entry is stale.** It lists `relaties.ts`, `articles.ts`, `machines.ts`, `reservations.ts` as frontend-only mocks with no backend route "yet" — all 4 now have real, mounted `apps/api/src/routes/*.ts` counterparts. `apps/web/src/api/overhead.ts` is the one module still genuinely 100% localStorage-only, and is the actual outstanding item that contradicts CLAUDE.md's "no new localStorage-only modules" rule (pre-existing, never migrated).
32. **Likely-unused dependencies in `apps/web/package.json`: `recharts`** (zero imports anywhere) **and possibly `@mantine/charts`** (only its CSS is imported in `main.tsx`; no chart component from it is used anywhere — `ArticleSankey.tsx` hand-rolls its own SVG).
33. **Machine "combined rate" formula (`machineRatePerHour + operatorRatePerHour`) is hand-inlined 4 times** instead of reusing the existing `machineRatePerHour()` helper in `apps/web/src/api/estimate.ts:59-66`: `ArticleCalculator.tsx:179` and `OverheadTab.tsx:310,311,361`.
34. **`MOCK_MUTATION_COUNTS`** (`VoorraadPage.tsx:143-145`) is keyed by old mock ids that can never match real Postgres UUIDs — unreachable now that mock phase has ended.
35. **Weight formula duplicated independently in frontend and backend** — `apps/api/src/services/weight.ts` and `apps/web/src/api/raw-materials.ts:64-79` (`computeWeightKg`, needed for live preview) implement the same volume formula with no shared source; currently in agreement but with no shared test.
36. **`EFFECTIEVE_MIN = 294` re-hardcoded** in `apps/web/src/utils/planningQueueUtils.ts:135` instead of importing the real constant from `planningUtils.ts:8` — currently equal by coincidence.
37. **`todosApi.update` is a dead wrapper** (`apps/web/src/api/todos.ts:7-8`) — backed by a working route but never called from any page/component. Related: the `notifyOnDue` field is always `false`, has no UI control, and nothing consumes it — fully vestigial.
38. **`DEFAULT_ORDER` export in `projectColumns.tsx:440` is unused** anywhere in the codebase.
39. **`/api/search` (`apps/api/src/routes/search.ts`) has no frontend caller** — `ArtikelenPage`/`RelatiesPage` both filter client-side per `features/36-search.md` — and additionally queries the empty `FinishedGood` table (see finding 4).
40. **Two near-duplicate "empty estimate" constants with diverging defaults**: `ArtikelenPage.tsx:20` (`marginPct: 0`) vs `ArtikelDetailPage.tsx:26` (`marginPct: 35`), same shape/purpose. Currently harmless (cost is 0 either way with empty nodes) but a latent inconsistency.
